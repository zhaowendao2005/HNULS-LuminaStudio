# Minimalist Frontend Design Rules

仅在明确调用此技能或用户明确要求应用此前端编写风格时遵循。

## 目标

以紧凑、可读、面向面板的 Lumina 风格编写渲染器 UI：

- 保持高密度但不拥挤
- 保持层级明显
- 优先使用文本层级而非装饰性容器
- 使次要文本可读；不要冲淡它
- 将颜色用作语义指导，而非装饰

## 适用范围

将此技能应用于：

- `LuminaStudio/src/renderer/src/views/**`
- `LuminaStudio/src/renderer/src/components/**`
- 渲染器端 Vue + Tailwind UI 工作

保留项目规则：

- 对于页面私有 UI，在模板类中保留 Tailwind
- 保留根定位类
- 遵循周围的 OrchestraFlow 浮动面板模式，除非用户要求有意偏离

## 第一步

编辑前：

1. 检查同一视图子树中的 1-2 个相邻组件
2. 尽可能重用它们的间距比例和排版密度
3. 如果用户要求新的视觉方向，仍要与相邻面板结构保持兼容

## 排版

除非用户另有要求，否则优先使用与 `IterationNodePanel.vue` 相同的密度。

- 面板标题：重用现有的 `system-xl-semibold`
- 区块标签：使用 `system-sm-semibold-uppercase` 或 `text-xs font-semibold uppercase`
- 主要行标签：优先使用 `text-[13px] font-semibold leading-[18px]`
- 次要内联文本：优先使用 `text-xs`
- 辅助文本：优先使用 `text-xs leading-5`

避免：

- 将过大的字段名用作英雄标题
- 在配置行内使用装饰性大字体
- 非常淡的灰色文本导致可读性下降

## 对比度

使用比默认冲淡占位符更深的灰色。

- 主要文本：`text-gray-800` 或 `text-gray-900`
- 次要文本：`text-gray-500` 或 `text-gray-600`
- 柔和但仍可读的文本：`text-gray-400`

避免：

- 大面积的 `text-gray-300`
- 几乎看不见的占位符或辅助文本
- 在一个小区域内使用多个不相关的强调色

## 间距

默认使用紧凑的面板间距。

- 面板头部内边距：约 `px-4 py-3`
- 区块间距：`space-y-2` 或 `space-y-3`
- 行垂直内边距：约 `py-2` 到 `py-3`
- 嵌套内容缩进：通常 `pl-3` 或 `pl-4`
- 行内部间隙：`gap-1`、`gap-1.5`、`gap-2`

避免：

- 大块空白垂直区域
- 卡片套卡片布局，除非明确需要
- 密集配置面板使用宽桌面内边距

## 布局

对于面板、编辑器和配置 UI：

- 优先使用分隔符而非盒子
- 优先使用 border-bottom 节奏而非重复卡片
- 优先使用左侧层级标记表示嵌套结构
- 将操作与其影响的内容保持内联
- 将保存/取消放在页脚，除非周围模式不同

对于嵌套的类模式结构：

- 每行或每组使用左边框
- 按深度改变左边框颜色
- 通过颜色加缩进保持嵌套可见，而非大容器

避免：

- 每个项目周围都有厚重的圆角卡片
- 虚线框，除非明确对占位符有用
- 每个控件都使用巨大的药丸形状

## 颜色

语义化使用强调色：

- 青色/天蓝色：选择器、类似变量的交互文本
- 翠绿色：结构、类对象语义、添加操作
- 玫瑰色：必填、破坏性、错误强调
- 紫罗兰色：数字或替代类型强调
- 琥珀色：更深层级或需要时的警告强调

对于嵌套层级：

- 0 级左标记：翠绿色
- 1 级左标记：青色
- 2 级左标记：紫罗兰色
- 3 级左标记：琥珀色

在一个组件内保持颜色映射稳定。

## 控件

优先使用轻量级控件：

- 类型选择：当选项集很小时，优先使用内联彩色文本选项
- 徽章：仅用于根、状态或小摘要
- 密集编辑器中的布尔切换：允许小型彩色文本芯片
- 破坏性操作：使用带清晰悬停状态的小图标按钮

当控件在密集编辑器中重复多次时，倾向于使用类文本控件而非带边框按钮。

## 表单编写

对于每个可编辑行：

1. 首先放置字段名
2. 将类型提示放在名称附近
3. 将必填标记放在类型或名称附近
4. 将默认值和描述放在同一行或紧接下方
5. 保持辅助文案简短

优先使用单行或一行半的行，而非高大的堆叠表单。

## 视觉层级

精确使用三个信息层级：

- 层级 1：字段或区块标识
- 层级 2：类型、默认值、选择器状态
- 层级 3：辅助文案

如果一行感觉繁忙：

- 在移除层级之前先移除边框
- 在移除对比度之前先移除背景填充
- 在将可读文本缩小到 `text-xs` 以下之前先压缩间距

## 反馈

不要在密集编辑器中留下永久性的笨重警告块，除非消息是持久且关键的。

优先使用：

- 保存时的浮动消息
- 在确切项目附近的紧凑内联强调

对于浮动消息：

- 从顶部中心出现
- 感觉像 iOS / Dynamic Island 反馈
- 保持文案简短

## 触发映射

当用户要求：

- "更紧凑"：首先减少内边距和行间距
- "像 IterationNodePanel"：将排版和区块密度与该面板对齐
- "不要胶囊"：用内联彩色文本选择替换药丸形状
- "不同层级不同色"：按深度为左标记和结构标签着色
- "灰色太淡"：将次要文本加深到 `gray-500/600`

## 检查清单

在此技能下完成 UI 工作之前，验证：

- 排版不会过大
- 次要文本可读
- 行紧凑
- 嵌套可见
- 控件轻量
- 颜色语义一致
- UI 匹配附近的 Lumina 面板而非通用 SaaS 卡片

## 输出风格

在编码任务中应用此技能时：

- 简要说明正在应用此技能
- 提及正在匹配哪个相邻组件
- 保持解释简短且专注于实现
