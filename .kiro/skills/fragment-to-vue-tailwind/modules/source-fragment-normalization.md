# 来源片段规整

## 目标

先把来源片段清洗成“可转写骨架”，再进入 Vue 改写。不要一边清洗一边重构，否则容易把视觉锚点和状态层级弄丢。

## 0. 先确认视觉真值与禁动项

- 把 demo、截图、参考组件、来源 HTML / JSX 视为视觉真值，默认不对它做审美重解释。
- 在开始清洗前，先标出不能擅自动的视觉锚点：
  - 外轮廓和主次层级
  - 宽高比例、留白、间距、对齐方式
  - 圆角、边框、阴影、背景层次
  - 字号、字重、字色、行高、文案换行节奏
  - 图标尺寸、位置、描边粗细、装饰元素
  - hover、selected、disabled、empty、error 等可见状态差异
- 清洗阶段只删除运行时噪音，不主动做“更规整”“更统一”“更像项目现有组件”的改造。

## 1. 先区分三类内容

### 1. 业务骨架

保留这些内容：

- 标题、正文、标签、按钮文案
- 图标、徽标、状态点
- 头部 / 主体 / 底部 / 分栏 / 条件项等结构层次
- hover、selected、disabled、empty 等真实状态语义

### 2. 视觉实现细节

保留后再转写：

- 宽高、圆角、边框、阴影、间距
- 文本字号、字重、颜色
- 绝对定位的小装饰、连接点、浮层

### 3. 运行时噪音

默认删除这些内容：

- `react-flow__*`
- `data-testid`
- 纯运行时 `data-id` / `aria-describedby` / `tabindex`
- 由 classnames 拼出来的 `false`、`undefined`
- 纯定位用的外层 `transform: translate(...)`

只有当某个属性直接承载业务含义或交互契约时，才允许保留。

## 2. 针对当前样例的判断

### 节点本体

`_Reference/Templete/条件分支节点-节点本体.html` 中：

- 最外层 `react-flow__node` 是运行时容器，不是业务组件根。
- 左右 handle、顶部 action bar、IF / ELSE 区块、条件条目、标题区属于业务可见结构。
- `group-hover:*`、绝对定位提示层、连接点按钮等可转写为 Vue 中的状态 UI，但不必照抄 React Flow DOM。

### 节点面板

`_Reference/Templete/条件分支节点-节点面板.html` 中：

- 外层绝对定位与拖拽宽度控制是宿主布局，不一定属于面板本体。
- 顶部标题、描述、页签、条件编辑区、底部“下一步”属于面板业务结构。
- `contenteditable`、按钮、条件行、占位文本等应转成 Vue 可控结构，不要原样复制为不可维护 DOM。

## 3. 清洗顺序

1. 删运行时包裹层。
2. 删无意义属性与脏 class。
3. 保留视觉骨架对应的层级，不要为了减少节点数提前压扁结构。
4. 把 inline style 中真正属于组件本体的内容转成 Tailwind 或域内局部样式。
5. 把宿主布局相关的定位样式移出组件职责。

## 4. 结果要求

清洗完成后，应当能回答：

- 组件真正的根节点是哪一个。
- 哪些层是业务层，哪些层只是宿主运行时层。
- 哪些状态值得进入 Vue `props` / `computed`。
- 哪些样式必须留在任务域局部 CSS 中。
- 哪些视觉锚点是本次转写中不允许擅自偏移的。

## 5. React / JSX 来源补充

如果来源不是静态 HTML，而是 React 组件 / JSX / TSX，再额外做这些判断：

- 把 `import`、`export default`、组件函数签名视为框架壳层，不视为业务骨架。
- 把 JSX 中的条件分支、列表渲染、片段结构视为真实界面骨架，继续保留后再映射到 Vue。
- 把 `useState`、`useMemo`、辅助函数拆成“真实 UI 状态”和“React 书写噪音”两类，只保留前者。
- 把图标组件、按钮事件、输入控件绑定视为视觉和交互锚点，不要因为它们写在 React 里就整体删除。
- 不要把 JSX 里已经表达清楚的尺寸、间距、排版和装饰，当成“后面再按项目风格重做”的可选项。
- 把只为 React key、调试、预览存在的实现细节视为噪音，默认不进入 Vue 输出。
