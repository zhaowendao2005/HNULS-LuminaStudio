# 任务域与样式边界

## 定义

把一次原型转写视为一个任务域。任务域的作用不是替代组件命名，而是给这次转写建立一个局部样式边界，避免公共样式泄漏，也减少外部样式反向污染。这个边界还承担另一层职责：保护来源片段的视觉真值，避免在接入项目样式体系时被“顺手改味”。

## 1. 根节点规则

根节点至少携带两类标识：

- 业务定位类：用于 DevTools 快速定位
- 任务域类：用于收敛局部公共样式

示例：

```vue
<template>
  <section class="wf-ifelse-node-panel frag-ifelse-node-panel flex flex-col">
    ...
  </section>
</template>
```

其中：

- `wf-ifelse-node-panel` 是业务定位类
- `frag-ifelse-node-panel` 是任务域类

## 2. 样式表达优先级

优先按下面顺序写：

1. 直接写在标签上的 Tailwind class
2. 仅在任务域内部生效的局部公共类
3. 已存在且语义完全匹配的项目类

不要反过来先写一堆抽象类，再把标签清空。这个 skill 的核心是“忠实转写”，不是“优先抽象”。
复用第 3 类样式时，前提必须是视觉等价；如果只能做到“差不多”，那就不要复用。

## 3. 什么样式可以抽成域内公共类

仅抽这些高频重复样式：

- 同一片段内重复 3 次以上的徽标盒子、条件条、标题行
- Tailwind 写起来非常噪音的伪元素或组合选择器
- 必须绑定到任务域根节点的轻量 reset

推荐形式：

```vue
<style scoped>
.frag-ifelse-node-panel :where(.frag-condition-chip) {
  @apply flex h-6 items-center rounded-md px-1 text-xs text-text-secondary;
}
</style>
```

## 4. 怎样限制公共样式影响范围

始终遵守这几条：

- 不写裸标签全局规则，如 `div {}`、`input {}`、`button {}`。
- 不写无前缀的共享类，如 `.title {}`、`.panel {}`。
- 所有补充样式都从任务域根类起步。
- 对输入框、按钮、文本域这类容易被全局样式污染的元素，显式写 `appearance-none`、字号、行高、颜色、背景。
- 不要为了复用项目公共样式而接受可见偏差，尤其是圆角、阴影、字号、字重、边框色、背景层次的偏差。

## 5. 怎样减少上级或全局样式的反向影响

默认使用“轻隔离”，不要一上来全量 reset：

- 在根节点显式声明本片段的字号、文字色、背景语义。
- 对易受影响的元素显式补齐 `font-size`、`line-height`、`font-weight`、`color`。
- 对依赖层叠上下文的局部浮层使用 `relative` / `absolute` / `z-*`，必要时给根节点加 `isolate`。

只有确认全局样式冲突很强时，才添加最小必要的局部 reset，而且仍要挂在任务域根类下。

## 6. 允许复用什么

可以复用：

- 项目已有的 token 颜色类
- 已存在的 utility class
- 与设计稿语义一致的通用排版类
- 视觉效果与来源片段可直接对齐的项目组件片段或局部样式

不要复用：

- 必须依赖祖先 DOM 才生效的样式
- 看不出语义来源的旧业务类
- 会把组件绑定到某个页面上下文的选择器
- 任何会把 demo / 参考组件改造成“项目默认风格”的旧样式资产
